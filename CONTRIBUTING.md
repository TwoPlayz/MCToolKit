# Contributing to MCToolKit

Thanks for helping! Bug reports, conversion problems, new mappings, extensions and pull
requests are all welcome. For questions, or to share a world that converts badly, join the
[Discord](https://discord.gg/y5mECmtban).

## Reporting a problem

Open an [issue](https://github.com/TwoPlayz/MCToolKit/issues) and include:

- the MCToolKit version (bottom of the sidebar, or Settings → About & Licenses),
- what you were doing (convert, prune, edit; which editions and game versions),
- what you expected and what happened, plus the debug log if there is one
  (Settings → *Show Debug Log*).

If a world is involved, never post the only copy. MCToolKit never modifies the input of a
conversion and keeps `_MCTBackup` copies when saving, but keep your own backup anyway.

## Setting up

Follow *Building from source* in the [README](README.md): Rust 1.85 or newer, a C compiler,
then `cargo build --release`. Use `--release` when trying the app; conversion and map
rendering are far slower in a debug build.

## Before you open a pull request

```
cargo test --workspace
```

A few tests read sample worlds from `C:\Users\<you>\Desktop\Worlds`. They skip themselves when
that folder is missing, so the suite passes without any worlds installed.

Please keep changes focused, match the style of the code around them, and add a test when you
fix a bug or add a conversion rule. If a change affects how worlds convert, say which sample
worlds you checked it against; conversion has not been verified inside Minecraft yet, so
any real-world testing is valuable.

## Project notes

- **Crates.** The workspace is split by job (NBT, Anvil, Bedrock, console saves, mappings,
  conversion, pruning, the Lua host, the CLI and the app); the table in the README lists them.
- **Mapping data.** The tables in `crates/mctk-mapping/data` are generated by the examples in
  `crates/mctk-mapping/examples`; `NOTICE.md` there records where each table comes from.
  Change the generator, not the generated file.
- **Update checks.** The app asks
  `https://api.github.com/repos/<owner>/<repo>/releases/latest` on startup. If you fork the
  project, change `REPO` in `crates/mctk-gui/src/update.rs`.
- **Third-party licences.** After changing dependencies, refresh
  `crates/mctk-gui/assets/rust-dependencies.tsv` and
  [`THIRD_PARTY_LICENSES.md`](THIRD_PARTY_LICENSES.md); both list the crates in `Cargo.lock`
  with their licences. If you add code, data or art from another project, add it to
  `THIRD_PARTY_LICENSES.md` too.

## Releases (maintainers)

Every push to `main` is built and tested on GitHub. To publish a release, raise `version` in
the workspace `Cargo.toml` (for example to `0.2.0`) and push: GitHub builds the Windows app and
command-line tool and publishes them as release `v0.2.0`. If that version is already released,
nothing is published. The in-app update check compares the release tag with the running
version, so always raise the version for a new release. See `.github/workflows/build.yml`.
